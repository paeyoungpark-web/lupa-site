Lupa.

AI 도구에서 내 Mac 파일 검색하기

Claude · Aside · Codex · Hermes 등 어떤 AI 도구에서든 Lupa로 찾게 만드는 방법. 설정은 한 줄이면 끝납니다.

등록할 명령은 어디서나 같습니다 
npx -y lupa-mcp

이 명령을 AI 도구의 MCP 서버 설정에 넣으면, 그 도구가 lupa_search(검색)와 lupa_read(문서 본문 읽기)를 쓸 수 있게 됩니다. 검색은 전부 이 Mac 안에서 끝납니다.

준비 (한 번만)

  1. App Store에서 Lupa 설치
  2. 앱 실행 → ⌘, → 폴더에서 검색할 폴더 등록 → 인덱싱 완료 대기
  3. Node.js 확인 — 터미널에서 node -v (없으면 nodejs.org)

도구별 설정

Claude Code

claude mcp add lupa -- npx -y lupa-mcp
자연어를 검색어로 바꿔주는 스킬까지 쓰려면: 
claude plugin marketplace add paeyoungpark-web/lupa-claude-plugin
claude plugin install lupa-file-search@lupa

Claude Desktop

Lupa 설정 ▸ 일반 ▸ "Claude Desktop에 연결…" 버튼 한 번이면 끝입니다(Lupa 2.0.1 이상).

직접 하려면 ~/Library/Application Support/Claude/claude_desktop_config.json:

{
  "mcpServers": {
    "lupa": {
      "command": "/bin/zsh",
      "args": ["-lc", "npx -y lupa-mcp"]
    }
  }
}

데스크톱 앱은 터미널의 PATH를 물려받지 않습니다. "command": "npx"로 적으면 서버가 뜨지 않으니 위처럼 로그인 셸로 감싸세요.

Aside (AI 브라우저)

Lupa 설정 ▸ 일반 ▸ "Aside에 연결…"(Lupa 2.0.1 이상). Aside를 완전히 종료(⌘Q)한 뒤 누르세요.

직접 하려면 Aside 설정 ▸ Plugins & MCPs ▸ 서버 추가 ▸ Command 칸에 npx -y lupa-mcp

Codex CLI

codex mcp add lupa -- npx -y lupa-mcp
codex mcp list   # lupa 가 보이면 성공

Hermes

~/.hermes/config.yaml의 mcp_servers: 아래에 추가합니다.

mcp_servers:
  lupa:
    command: npx
    args: ["-y", "lupa-mcp"]

그 밖의 MCP 지원 도구

그 도구의 stdio MCP 설정에 아래 중 맞는 형식으로 넣으세요.

PATH를 못 찾는 GUI 앱/bin/zsh / ["-lc", "npx -y lupa-mcp"]

왜 "명령줄"이 아니라 MCP인가

요즘 에이전트는 셸 명령을 자기 샌드박스 안에서 실행합니다. Lupa의 명령줄 도구는 App Store 규정에 따라 샌드박스로 서명돼 있어서, 샌드박스 안에서 또 띄우면 macOS가 기동을 막습니다.

환경명령줄 도구 직접 실행
터미널 · Claude Code정상
Aside 셸 도구종료 코드 133
Codex 샌드박스종료 코드 134

MCP 서버는 샌드박스 밖에서 실행됩니다. 그래서 같은 도구라도 MCP로 등록하면 정상 동작합니다.

연결 확인

도구 목록에 lupa_search와 lupa_read가 보이면 성공입니다. "Lupa로 계약서 찾아줘"처럼 물어보세요.

  • lupa_search — 파일명과 문서 본문 검색. 폴더명 검색 옵션도 있습니다.
  • lupa_read — 찾은 파일의 본문 텍스트를 받습니다. 파일을 열지 않고 색인에 저장된 텍스트를 돌려주므로, 에이전트가 직접 못 읽는 한글(HWP)·스캔 PDF도 요약할 수 있습니다.

문제 해결

증상해결
종료 코드 133 / 134, Trace/BPT trap 샌드박스 안에서 명령줄 도구를 실행한 것입니다. MCP로 등록하세요. 다시 시도하거나 파일을 복사해도 같은 이유로 실패합니다.
npx: command not found GUI 앱이 PATH를 못 봅니다. /bin/zsh -lc "npx …" 형태로 감싸세요.
index_not_found Lupa 앱에서 폴더를 등록하고 인덱싱이 끝나기를 기다리세요.
첫 호출이 10~20초패키지를 처음 내려받는 중입니다. 두 번째부터는 즉시입니다.
"악성 코드가 없음을 확인할 수 없습니다" 경고 에이전트가 소스에서 직접 빌드한 파일입니다. 지우고 MCP로 등록하세요. App Store에서 받은 앱과는 무관합니다.

에이전트에게 주는 규칙

스킬이나 프롬프트에 그대로 붙여넣으면 우회 시도를 막을 수 있습니다.

로컬 파일을 찾을 때는 find·grep·mdfind 대신 Lupa를 쓴다.

1. lupa_search / lupa_read 도구가 있으면 그것만 쓴다.
2. 도구가 없으면 사용자에게 Lupa MCP 등록을 안내하고 멈춘다.
3. 다음은 절대 하지 않는다 — 전부 실패하거나 결과를 망친다.
   - lupa-search 바이너리를 셸로 실행 (샌드박스에서 133·134로 죽는다)
   - 소스에서 빌드 (서명 없는 파일 → macOS 보안 경고)
   - 색인 SQLite를 직접 조회 (한국어 토크나이저·랭킹이 빠져 결과가 크게 나빠진다)
4. 검색 문법: n:이름 c:내용 f:폴더 -제외 "정확구문" 종류:PDF 크기:>10mb 날짜:이번주 .hwp 계약*
5. 본문이 필요하면 lupa_read로 받는다.

Obsidian 같은 앱은 "등록"입니다

Obsidian·메모 앱은 에이전트가 아니라 파일을 만드는 앱입니다. 볼트 폴더를 Lupa에 등록하면 Markdown 본문까지 검색됩니다. 클라우드 드라이브(Google Drive·OneDrive·iCloud)도 같은 방식으로 폴더만 등록하면 됩니다.

에이전트에게 무엇을 주는가

  • 네트워크를 쓰지 않습니다. 검색은 전부 이 Mac 안에서 끝납니다.
  • 파일 접근 권한은 주지 않습니다. 에이전트가 받는 것은 Lupa가 미리 색인해 둔 텍스트뿐입니다.
  • 색인에는 사용자가 등록한 폴더만 들어갑니다.
