Lupa.

Search your Mac from any AI tool

How to let Claude, Aside, Codex, Hermes — any AI tool — find files with Lupa. Setup is a single line.

The command is the same everywhere 
npx -y lupa-mcp

Put this in your AI tool's MCP server settings and it gains two tools: lupa_search (search) and lupa_read (read a document's text). Everything runs on this Mac — no network.

Setup (once)

  1. Install Lupa from the App Store
  2. Open the app → ⌘, → add the folders you want searched → wait for indexing
  3. Check Node.js — run node -v (get it at nodejs.org)

Per-tool setup

Claude Code

claude mcp add lupa -- npx -y lupa-mcp
To also install the skill that turns plain language into Lupa queries: 
claude plugin marketplace add paeyoungpark-web/lupa-claude-plugin
claude plugin install lupa-file-search@lupa

Claude Desktop

Lupa Settings ▸ General ▸ "Connect to Claude Desktop…" — one click (Lupa 2.0.1+).

Or edit ~/Library/Application Support/Claude/claude_desktop_config.json:

{
  "mcpServers": {
    "lupa": {
      "command": "/bin/zsh",
      "args": ["-lc", "npx -y lupa-mcp"]
    }
  }
}

Desktop apps don't inherit your terminal's PATH. "command": "npx" alone will not start — wrap it in a login shell as shown.

Aside (AI browser)

Lupa Settings ▸ General ▸ "Connect to Aside…" (Lupa 2.0.1+). Quit Aside (⌘Q) first.

Or in Aside: Settings ▸ Plugins & MCPs ▸ add a server ▸ Command: npx -y lupa-mcp

Codex CLI

codex mcp add lupa -- npx -y lupa-mcp
codex mcp list   # lupa should appear

Hermes

Add it under mcp_servers: in ~/.hermes/config.yaml.

mcp_servers:
  lupa:
    command: npx
    args: ["-y", "lupa-mcp"]

Any other MCP-capable tool

Use whichever shape that tool's stdio MCP settings expect.

ShapeValue
Single command linenpx -y lupa-mcp
command + argsnpx / ["-y", "lupa-mcp"]
GUI app without shell PATH/bin/zsh / ["-lc", "npx -y lupa-mcp"]

Why MCP, not the command line

Modern agents run shell commands inside their own sandbox. Lupa's command-line tool is sandbox-signed (an App Store requirement), and macOS blocks a sandboxed binary launched from inside another sandbox.

EnvironmentRunning the CLI directly
Terminal · Claude Codeworks
Aside shell toolexit code 133
Codex sandboxexit code 134

MCP servers start outside that sandbox, so the same tool works once Lupa is registered as MCP.

Check the connection

Success looks like lupa_search and lupa_read showing up in the tool list. Try asking: "find my contracts with Lupa".

  • lupa_search — search file names and document contents, with an option to match folder names.
  • lupa_read — returns a file's text from the index without opening the file, so agents can summarise formats they cannot parse (Hangul HWP, scanned PDFs).

Troubleshooting

SymptomFix
Exit code 133 / 134, Trace/BPT trap The CLI was run inside a sandbox. Register Lupa as MCP instead — retrying or copying the binary fails for the same reason.
npx: command not found The GUI app can't see your PATH. Wrap it: /bin/zsh -lc "npx …"
index_not_found Add folders in the Lupa app and wait for indexing to finish.
First call takes 10–20snpx is downloading the package. Later calls are instant.
"malware cannot be verified" warning That file was built from source by an agent. Delete it and use MCP. It has nothing to do with the App Store app.

Rules to give your agent

Paste this into a skill or system prompt to stop agents from improvising workarounds.

Use Lupa instead of find/grep/mdfind for local file lookups.

1. If lupa_search / lupa_read are available, use only those.
2. If they are missing, tell the user to register the Lupa MCP server, then stop.
3. Never do these — they all fail or ruin the results:
   - running the lupa-search binary through a shell (killed with 133/134 in sandboxes)
   - building the CLI from source (unsigned binary -> macOS security warning)
   - querying Lupa's SQLite index directly (skips the tokenizer and ranking; results get far worse)
4. Query syntax: n:name c:content f:folder -exclude "exact phrase" kind:pdf size:>10mb date:week .hwp report*
5. Need the text? Use lupa_read.

Obsidian and friends: add the folder

Obsidian and note apps aren't agents — they make files. Add the vault folder in Lupa and your Markdown is searchable by content. Cloud drives (Google Drive, OneDrive, iCloud) work the same way.

What the agent actually gets

  • No network. Every search stays on this Mac.
  • No file access. The agent only receives text Lupa already indexed.
  • The index contains only the folders you added.
